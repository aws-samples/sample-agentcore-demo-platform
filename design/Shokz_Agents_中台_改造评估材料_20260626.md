# Shokz Agents 中台改造评估材料

评估日期：2026-06-26  
客户目标上线日期：2026-07-15  
参考需求文档：`design/PRD_Shokz_Agents中台_v1.0_20260625.md`  
配套 Excel 清单：`design/Shokz_Agents_中台_改造功能清单_20260626.xlsx`

## 1. 总体结论

当前项目已经具备企业 Agent 平台的底座能力，包括 Chat 会话、Agent Runtime、工作区、Skill 数据模型、Skill Marketplace、工作流、MCP、文件工作区、流式输出和部分安全 Hook。

但客户 PRD 的 V1 目标更偏向“Skill 能力资产中台”：围绕 Skill 的上传、解析、审核、发布、市场、安装、调用、团队可见性、运行策略、审计和管理后台形成闭环。当前项目已有可复用基础，但缺少完整的 Skill 生命周期和面向企业管理的产品化能力。

按完整 PRD V1 范围评估，改造量较大，不建议承诺在 2026-07-15 一次性完整上线。更可控的方案是 2026-07-15 交付 V1 Lite 试点版，先完成核心使用闭环，后续按 2 周一个阶段补齐企业治理能力。

## 2. 最大改造模块

改造量最大的模块是：Skill 能力资产闭环。

原因：

- 涉及前端、后端、数据库、权限、审核、安装、调用、安全、审计和管理后台，不是单页面调整。
- 当前项目虽然已有 `skills`、`skill_marketplace`、`skill_scan_results` 等模型，但 PRD 要求的是从上传到调用的完整业务流程。
- Skill 调用还需要和 Chat、Workspace、Agent Runtime、权限策略联动。
- 企业可见性、团队授权、管理员审批、SkillSpector/Runtime Profile 都属于跨模块能力。

从工作量排序看：

| 排名 | 模块 | 改造量 | 说明 |
|---|---|---:|---|
| 1 | Skill 能力资产闭环 | 最大 | 上传、解析、扫描、审批、发布、市场、安装、调用、审计 |
| 2 | 权限 / 团队 / 管理后台 | 大 | Authing、RBAC、部门、团队申请、审批流、管理员视图 |
| 3 | Workspace / Project / 文件与产物 | 中大 | 默认工作区、项目工作区、文件上传、产物预览、下载 |
| 4 | Chat 交互与 Skill 调用体验 | 中 | `/` Skill 命令、文件上下文、模型选择、上下文延续 |
| 5 | 安全与运行策略 | 中大 | Runtime Profile、工具白名单、扫描、执行策略、审计 |

## 3. 与当前项目的主要差异

### 3.1 已有能力，可复用

- Chat 会话、消息存储、SSE 流式输出。
- Agent Runtime 抽象，支持 `claude / agentcore / openclaw / berriai`。
- 工作区机制，可为 Agent 准备 workspace。
- Skill 基础表、Marketplace 表和部分安装/导入能力。
- 文件上传、工作区文件浏览、产物预览的基础能力。
- Workflow、MCP、调度、Webhook 等平台能力。
- 部分安全 Hook：危险命令拦截、二进制读取拦截、Skill 白名单。

### 3.2 主要缺口

- Authing OIDC + PKCE 未完整实现，目前主要是 local / Cognito。
- PRD 角色体系缺失：超级管理员、部门管理员、普通用户、团队管理员等需要重新映射。
- 用户部门、工号、组织层级、团队申请审批流程缺失。
- Skill zip 上传、`SKILL.md` 解析、版本管理、元数据抽取不完整。
- Skill 审核、团队审核、管理员后台审批未形成闭环。
- Skill Market 可复用，但需要按 PRD 调整可见性、安装范围、分类、详情页和搜索。
- 用户全局安装 Skill、项目安装 Skill、团队可见 Skill 需要补齐。
- Chat 中 `/` 唤起 Skill 的交互和后端调用路由缺失。
- Runtime Profile、SkillSpector、安全策略和审计报表不足。
- 上下文自动压缩能力不完整，目前更多依赖 session resume 和最近消息注入。

## 4. Harness 能力判断

项目有 Harness 底座，但不是完整产品化 Harness。

已具备：

- Agent Runtime 抽象，可切换不同运行时。
- Claude SDK / AgentCore / BerriAI 等运行路径。
- 会话 resume。
- workspace 隔离。
- 工具调用 Hook。
- 流式事件协议。
- BerriAI 运行时可对接 K8s sandbox harness。

不足：

- 没有完整自动上下文压缩。
- 没有管理端可配置 Runtime Profile。
- 没有按 Skill 配置工具、网络、文件、预算、审批策略的完整模型。
- 没有完整的 Skill 调用审计和策略回放。

建议：7 月 15 日前复用现有 Harness 底座，不重做运行框架；只补最小 Skill 调用、权限、审计闭环。完整 Runtime Profile 和自动压缩放到后续阶段。

## 6. AI Agent 对人天的影响

AI Agent 能减少人天，但不能把企业级改造压缩到非常低。

适合 AI Agent 提效的部分：

- 接口、DTO、schema、repository、service 的批量开发。
- 前端页面和组件改造。
- Excel 清单、差异文档、测试用例、验收脚本生成。
- Skill 解析、元数据抽取、批量迁移脚本。
- 单元测试和回归测试补充。

不适合完全依赖 AI Agent 的部分：

- 权限模型设计。
- Authing 对接与生产环境联调。
- 审批流程边界确认。
- 安全策略和企业验收。
- 跨模块联调和上线决策。

合理预期：AI Agent 可减少约 25% - 35% 开发投入。若流程、需求和接口确认很顺畅，局部模块可达到 40% 左右提效。

## 7. 2026-07-15 可上线范围建议

建议上线 V1 Lite 试点版，不承诺完整 PRD。

### 7.1 建议纳入

- Authing 基础登录对接，前提是客户及时提供租户、Client ID、回调地址和测试账号。
- Chat 主流程。
- 默认工作区基础能力。
- 文件上传作为上下文。
- 工作区文件列表、预览、下载。
- Skill Market 浏览、搜索、详情。
- Skill 安装 / 卸载到个人或工作区。
- Chat 中 `/` 唤起已安装 Skill。
- Skill zip 上传和 `SKILL.md` 基础解析。
- 管理员最小审批：通过 / 拒绝 / 发布。
- 基础审计记录。

### 7.2 建议延期

- 完整团队申请与团队审批。
- 完整四级可见性策略。
- 复杂部门管理员权限。
- 完整 Runtime Profile。
- 完整 SkillSpector。
- 审计报表和运营分析。
- 多租户高级配额和预算管理。
- 全量项目工作区和复杂产物管理。

- 明确 V1 Lite 范围。
- 确认 Authing 参数、角色映射、回调地址。
- 冻结 Skill 数据模型和审批状态流。
- 确认 2026-07-15 验收口径。

### Phase 4：管理后台 / 权限治理

- 用户、部门、团队、角色、审批管理。

- Runtime Profile。
- SkillSpector 完整化。
- 审计报表。

## 9. 推荐执行策略

- 对客户沟通时，把 2026-07-15 定义为“试点上线 / V1 Lite”，不要定义为完整 V1。
- 所有开发围绕 Skill 使用闭环优先：登录、发现、安装、调用、产出、审批。
- 管理治理能力分阶段补齐，避免第一阶段被权限和审批复杂度拖垮。
- 现有 Agent Runtime 和 workspace 能力优先复用，不重做 Harness。
- Excel 功能清单作为估算主表，后续可在其中补负责人、排期、状态和实际人天。
